# oxi v0.1.1 — Beta

A patch release focused on mailbox synchronization, search correctness, reply
handling, and reliable Nix builds.

## Changes

### Fixed

- Recover missing older message headers after interrupted backfills and improve
  mailbox update recovery, including stale synchronization races.
- Invalidate the Sent cache after successful IMAP appends.
- Correct search-index removal and signature formatting.
- Improve sender privacy and reply handling.
- Fix Nix builds by bundling fonts for offline builds, including backend test
  fixtures, and running Next.js static exports with Node.js.

### Changed

- Update frontend dependencies to current stable releases.

## Upgrade from v0.1.0

1. Back up the persistent `/data` volume, including contacts and calendar data.
2. Change your deployment image to `ghcr.io/c0h1b4/oxi:v0.1.1` and recreate the
   container, keeping the same configuration and persistent volume.
3. Sign in again after the server restarts. Check mailbox updates, Sent messages,
   replies, and search before removing your backup or previous image.

For Nix deployments, update the source revision to `v0.1.1` and rebuild. See
[the Nix deployment guide](https://github.com/c0h1b4/oxi/blob/v0.1.1/nix/README.md).

## Beta cautions and known limitations

- The 0.x series remains beta software; breaking changes may occur before 1.0.
- oxi requires an existing IMAP/SMTP account; it is not a mail server.
- Sessions and account credentials are held in memory, so restarts require login.
- Search covers locally cached/indexed mail. Background body indexing is opt-in
  and gradual.
- Contacts and calendar events are stored locally; CardDAV/CalDAV synchronization
  is not implemented. Do not discard the persistent data volume.
- IMAP STARTTLS and Sieve/server-side filter management are not supported.
- Subpath deployments still require matching frontend `NEXT_PUBLIC_BASE_PATH`
  and backend `BASE_PATH` settings.

## Distribution

Docker image: `ghcr.io/c0h1b4/oxi:v0.1.1` (also tagged `0.1.1`). The `latest` tag
tracks `main`, not a stable release. GitHub provides source archives; standalone
binaries are not published. This release is published as a GitHub prerelease.
