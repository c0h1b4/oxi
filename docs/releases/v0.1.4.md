# oxi v0.1.4 — Beta

A patch release improving the compose editor and introducing automated,
CI-validated releases. This is the next published beta after v0.1.2; v0.1.3
was not published. The changes below cover both versions.

## Changes

### Fixed

- Restore list markers and indentation in the compose editor, including nested lists.
- Reset HTML source editing mode for each new message while preserving it on undo-send.

### Added

- Editable HTML source mode for composing, saving, and sending messages, with a
  warning that rich-text edits may remove unsupported HTML.

### Changed

- Split CI into reusable workflows behind one required `CI Gate`, with parallel
  Rust/frontend checks and cached Nix flake evaluation.
- Publish containers to GHCR and Docker Hub, then create the GitHub release from
  the exact commit validated by main CI.
- Add a manual full Nix build workflow and validate explicit pre-push boundaries
  for manual release recovery.
- Require version bumps for releases and keep package versions synchronized.
- Make Docker `latest` track numbered releases and `edge` track `main`; add
  floating minor tags and major tags starting at 1.0.

## Upgrade from v0.1.2

1. Back up the persistent `/data` volume, including contacts and calendar data.
2. Change your deployment image to `ghcr.io/c0h1b4/oxi:v0.1.4` and recreate the
   container, keeping the same configuration and persistent volume.
3. Sign in again after the server restarts. Check composing, nested lists, HTML
   source editing, drafts, and sending before removing your backup or previous image.

For Nix deployments, update the source revision to `v0.1.4` and rebuild. See
[the Nix deployment guide](https://github.com/c0h1b4/oxi/blob/v0.1.4/nix/README.md).

## Beta cautions and known limitations

- The 0.x series remains beta software; breaking changes may occur before 1.0.
- oxi requires an existing IMAP/SMTP account; it is not a mail server.
- Sessions and account credentials are held in memory, so restarts require login.
- Search covers locally cached/indexed mail. Background body indexing is opt-in
  and gradual.
- Contacts and calendar events are stored locally; CardDAV/CalDAV synchronization
  is not implemented. Do not discard the persistent data volume.
- IMAP STARTTLS and Sieve/server-side filter management are not supported.
- Subpath deployments still require matching frontend `NEXT_PUBLIC_BASE_PATH`
  and backend `BASE_PATH` settings.

## Distribution

Docker images are published to GHCR and Docker Hub. The GHCR image is
`ghcr.io/c0h1b4/oxi:v0.1.4` (also tagged `0.1.4`). The `latest` and `0.1` tags
track numbered releases; `edge` tracks `main` and may include unreleased changes.
GitHub provides source archives; standalone binaries are not published.
This release is marked Latest on GitHub; the 0.x series remains beta software.
